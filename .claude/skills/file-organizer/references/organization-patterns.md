# Organization patterns

Load this reference only when the user has not defined a useful structure and a non-trivial collection needs grouping.

## Selection order

Prefer, in order:

1. the user's explicit structure or naming convention;
2. an existing coherent structure already used by the collection;
3. recognizable project or purpose groupings;
4. lifecycle/state groupings when they aid retrieval;
5. file type or date only when those dimensions genuinely improve retrieval.

Avoid mixing unrelated grouping dimensions at the same level without a clear reason.

## Naming

Preserve established naming conventions when they are coherent. Preview batch renames and validate collisions. Do not remove dates, versions, identifiers, or download suffixes unless they are known to be redundant rather than meaningful.

## Archiving

Archive when the user wants material retained but inactive. Age is only a candidate signal; it is not proof that a file is safe to archive or delete.

## Review / quarantine

When classification is uncertain, leave the item in place by default. If the user approves a staging area, use a review/quarantine location and include every staged move in the rollback manifest.
