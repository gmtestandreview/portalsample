# Framework Routing

Load this reference when the task requires selecting, combining, or explaining project-management, agile, business-analysis, or portfolio guidance.

## Australian public-sector precedence

For Australian public-sector work, first establish jurisdiction and binding governance. For Commonwealth whole-of-government digital, procurement, risk, protective-security, cyber, architecture, or digital-service obligations, use `references/australian-government-context.md` before generic framework guidance.

Frameworks are practice lenses. They do not establish legal authority, delegation, procurement approval, policy applicability, or security risk acceptance.

## Routing rules

Use the smallest source set that answers the question. Current law, mandatory policy, contracts, agency governance, delegations, and approved baselines take precedence.

## Lifecycle tailoring heuristic

Use predictive delivery where the work can be planned with useful stability and baseline control is important.

Use adaptive delivery where learning, changing needs, and frequent feedback materially reduce delivery risk.

Use hybrid delivery where governance, funding, assurance, or approval points need plan-driven control while solution discovery and implementation benefit from iteration.

Always record:

- the uncertainty being managed;
- the governance constraint being respected;
- the value of feedback or staged delivery;
- the main dependencies;
- the point at which the lifecycle choice will be reviewed.

## Combining frameworks

Do not mechanically stack ceremonies, roles, or artefacts from multiple frameworks.

When combining guidance:

1. Start with the organisation's governance model and required decision rights.
2. Add only practices that solve a stated delivery or assurance need.
3. Remove duplicate ceremonies, reports, and approval layers.
4. Preserve one clear owner for each decision and artefact.
5. Explain any terminology mapping if two frameworks use different names for similar concepts.
