## Migration Risks To Track

- `AuthenticatedElement` and `PreConditions` drive several route outcomes that
  are not visible from route paths alone, including branch selection, terms
  acceptance, and forced account/contact completion.
- Browser refresh/close protection is intentionally absent from
  `RouteLeavingGuard`; the `onbeforeunload` handler is commented out. Any future
  decision to restore it requires updating `UnsavedFormPrompt`, the guard
  stories, and the explicit exclusion note in the Component Coverage Matrix row
  above.

## Completion Definition

Storybook coverage is complete for migration only when all of the following are
true:

1. Every user-visible route family has at least one route-level story that shows
   the real shell, realistic mocked data, and core empty/error/success states.
2. Every shared component family that renders user-facing UI has either
   dedicated stories or an explicit “not needed in Storybook” decision.
3. Authentication, validation, and guard behaviour are represented by documented
   harness stories where direct browser redirects are not practical.
4. Dashboard, RFQ, account, contact, quote-acceptance, quotation, and
   measurement-report flows all have scenario coverage for their dominant
   states.
5. Storybook becomes the canonical place to review migration parity for layout,
   states, content hierarchy, and interaction affordances.

The threshold is not yet met. The current recursive source gate and closure
receipts are the release criteria; family-level story presence is not a
substitute.

## Plan to Reach Full Coverage

### Phase 1: Foundation

- Harness capability is implemented in
  `ClientApp/src/storybook/storybookHarness.tsx`; source and route closure
  remain pending.

### Phase 2: Design System and Shared UI

- Focused evidence exists for selected families including `Inputs`, `Buttons`,
  forms, and route consumers.
- Recursive export classification, meaningful state claims, and remaining
  edge-state reviews are still open.

### Phase 3: Route Flows

- Existing dashboard, home/get-started, help, auth, account, contact, RFQ,
  accept-quote, quotation, measurement-report, success, and error stories remain
  retained evidence.
- MSW-backed contracts are exercised by focused stories, while route-harness
  isolation and current receipt coverage remain incomplete.

### Phase 4: Closure

- Coverage drift remains one input to closure, not proof of complete source
  evidence.
- Route-family exclusions remain documented, but each must still have an
  explicit manifest rationale.
- The migration-readiness gate and serial closure launcher remain open work;
  passing focused story tests does not qualify closure.
