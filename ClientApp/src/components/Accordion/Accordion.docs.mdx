## Accordion Components

The Accordion system provides expandable/collapsible sections for organizing complex information. It consists of two key components: `CustomAccordion` (the container) and `CustomAccordionBody` (individual items).

### Use Cases

- **Multi-step wizards** — Accordion-based form workflows
- **FAQ sections** — Frequently asked questions
- **Settings panels** — Grouped configuration options
- **Product specifications** — Detailed information organization
- **Disclosure hierarchies** — Progressive information revelation

### Key Features

- **Keyboard Navigation** — Native Bootstrap accordion button interaction
- **ARIA Semantics** — Button expansion state and panel relationships from React Bootstrap
- **Multi-line Headers** — Support for complex header layouts
- **Bootstrap Integration** — NMI design system styling
- **Default first section** — The wrapper opens the first item by default

## Implementation Guide

### Basic Accordion Setup

```tsx
import { CustomAccordion, CustomAccordionBody } from '@/components/Accordion';

export function BasicAccordion() {
  return (
    <CustomAccordion>
      <CustomAccordionBody 
        eventKey="0"
        name="Section One"
      >
        Content for section one
      </CustomAccordionBody>
      <CustomAccordionBody 
        eventKey="1"
        name="Section Two"
      >
        Content for section two
      </CustomAccordionBody>
    </CustomAccordion>
  );
}
```

### Multi-Line Header Example

```tsx
import { CustomAccordion, CustomAccordionBody } from '@/components/Accordion';

export function MultiLineAccordion() {
  return (
    <CustomAccordion>
      <CustomAccordionBody 
        eventKey="0"
        name="Organization Name"
        namePartTwo="ABN: 12 345 678 901"
        namePartThree="Type: Educational Institution"
      >
        Detailed organization information goes here...
      </CustomAccordionBody>
    </CustomAccordion>
  );
}
```

The generated Controls and ArgTypes above are the source of truth for
`CustomAccordion` props. `CustomAccordionBody` is demonstrated through the
stories on this page; keep its prop names and descriptions in TypeScript and
JSDoc rather than duplicating a hand-maintained MDX API table.

## Multi-Line Header Structure

The header supports three levels of information:

```tsx
<CustomAccordionBody
  eventKey="0"
  name="Main Title"
  namePartTwo="Secondary Information"
  namePartThree="Tertiary Information"
>
  Content here
</CustomAccordionBody>
```

CSS classes for styling:
- `accordion-body-name` — Primary header (bold/large)
- `accordion-body-name-part-two` — Secondary info (smaller text)
- `accordion-body-name-part-three` — Tertiary info (smallest)

## Accessibility Features

### Keyboard Navigation

- `Tab` — Navigate between accordion headers
- `Enter` / `Space` — Toggle section expand/collapse

### Screen Reader Support

- Proper `role="button"` attributes on headers
- `aria-expanded` indicates open/closed state
- `aria-controls` links header to content panel
- Descriptive labels for each section

### Focus Management

- Visible focus indicators on all interactive elements
- Logical tab order through accordion items
- Focus remains on clicked header after toggle

## Best Practices

✅ Use meaningful, descriptive headers  
✅ Keep content organized and scannable  
✅ Use multi-line headers for complex information  
✅ Ensure keyboard navigation works smoothly  
✅ Test with screen readers  
✅ Provide clear visual indication of expanded state

❌ Don't hide critical information in collapsed sections  
❌ Don't use for simple on/off toggles (use Switch instead)  
❌ Don't nest accordions too deeply (2-3 levels maximum)  
❌ Don't make all items expanded by default  
❌ Don't use ambiguous headers
