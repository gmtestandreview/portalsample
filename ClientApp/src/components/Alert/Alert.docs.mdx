## Alert Components

The Alert component system provides visual feedback and important information to users through four distinct variants: Success, Info, Warning, and Error. Each variant uses appropriate colors, icons, and ARIA announcements for accessibility.

### Use Cases

- **Success alerts** — Confirmation of completed actions
- **Info alerts** — General information and tips
- **Warning alerts** — Cautionary messages requiring attention
- **Error alerts** — Critical errors blocking user action

### Accessibility Features

- **ARIA Live Regions** — Automatically announce alerts to screen readers
- **Semantic HTML** — Proper heading and paragraph structure  
- **Color + Icons** — Not reliant on color alone to convey meaning
- **Dismissible Options** — Close button with proper focus management

## Implementation Examples

### Basic Success Alert

```tsx
import { AlertSuccess } from '@/components/Alert';

export function SuccessExample() {
  return (
    <AlertSuccess>
      Your changes have been saved successfully!
    </AlertSuccess>
  );
}
```

### Info Alert

```tsx
import { AlertInfo } from '@/components/Alert';

export function InfoExample() {
  return (
    <AlertInfo>
      Please note: The system will be under maintenance on Sunday.
    </AlertInfo>
  );
}
```

### Warning Alert

```tsx
import { AlertWarning } from '@/components/Alert';

export function WarningExample() {
  return (
    <AlertWarning>
      <strong>Notice:</strong> Your session will expire in 5 minutes due to inactivity. 
      Please save your work to avoid losing data.
    </AlertWarning>
  );
}
```

### Dismissible Error Alert

```tsx
import { AlertError } from '@/components/Alert';
import { useState } from 'react';

export function DismissibleErrorExample() {
  const [show, setShow] = useState(true);

  if (!show) return null;

  return (
    <AlertError canClose onClose={() => setShow(false)}>
      An error occurred while processing your request. Please try again.
    </AlertError>
  );
}
```

## Component Variants

| Type | ARIA live behaviour | Use for |
| --- | --- | --- |
| Success | Polite | Successful actions |
| Info | Polite status messaging | Information messages |
| Warning | Polite alert messaging | Cautions and tips |
| Error | Assertive alert messaging | Errors and failures |

## Dismissible Alerts

All alert variants support a dismissible mode by setting `canClose` and
providing the `onClose` callback:

```tsx
<AlertSuccess canClose onClose={handleClose}>
  Success message with close button
</AlertSuccess>
```

`canClose` controls whether the close button appears. `onClose` receives the
dismiss action when the close button is used.

## ARIA Announcements

- **Success/Info/Warning** use `aria-live="polite"` for non-urgent announcements
- **Error** uses `aria-live="assertive"` for immediate, urgent announcements
- All alerts include proper `role="alert"` attributes
- Automatically announced to screen readers when content changes

## Styling with NMI Design System

Each alert variant uses Bootstrap alert variants and the NMI theme tokens from
`ClientApp/src/styles/_variables.scss` and `ClientApp/src/styles/_alert.scss`.
Keep colour values in SCSS and the Style Guide swatches rather than copying
hex values into component MDX.

## Best Practices

✅ Use appropriate severity level for the message  
✅ Keep messages concise and actionable  
✅ Use multiple lines for complex information  
✅ Provide a close button for longer-lived alerts  
✅ Test with screen readers to verify announcements  
✅ Use in forms to show validation results

❌ Don't rely solely on color to convey meaning  
❌ Don't include too much text (keep under 2-3 sentences)  
❌ Don't auto-close error alerts without user confirmation  
❌ Don't nest alerts within other alerts  
❌ Don't use as primary content area
