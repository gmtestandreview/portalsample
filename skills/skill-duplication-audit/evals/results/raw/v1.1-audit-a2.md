## (a) Six adversarial scenarios
1. Sequential pair. Plan-skill A, execute-skill B; user says "plan and execute". Step 3 Q2 asks "alternatives for the same task": no, so output feeds input, so Complementary. But Complementary says "should not normally activate both", and Step 4 intentional composition says "both should activate". Both fit; the request activates both. AMBIGUOUS.
2. R1 itself. conventional-commit-writer has an output format. Guard lists "output" as specialization, so Partial overlap. expected.md says True duplicate. The rule as written gives the WRONG answer on the skill's own test.
3. Gotcha-only subset. S is a strict subset of B, same outcome, but S carries unique edge-case gotchas and evals. Guard's list (domain, stage, safety, tools, output) omits gotchas; Step 7 preservation list includes them. True duplicate or Partial? AMBIGUOUS.
4. One-sided boundary. A's description says "Not for B"; B's says nothing. Step 2: "contradicted/incomplete" so continue. Q2 yes, so Partial overlap. "Boundary docs needed" = pairs with no current authoritative boundary. Half-existing boundary: count undefined.
5. Four-chain. A=B, B=C, C=D duplicates, none a hub. Non-transitive guard covers A/C only. Cluster definition (all pairs duplicates) fails, hub exception needs 3. Group NHR even if A-D are all duplicates and consistent? Trace unresolved.
6. Explicit pair plus hub. User asks only A-B. Guard says evaluate A-C "in every mode", counted under Pairs evaluated. Explicit mode now reports 2 pairs; "Mode: explicit pairs" is arguably false and contradicts "evaluate any pair the user asks".

## Findings (severity ranked)
- High H1: Complementary vs composition. Fix: Complementary = "should not normally activate both for one request; if both are meant to activate together, use Partial overlap with intentional composition."
- High H2: R1 contradicts guard. Fix: "output means a distinct deliverable or template, not a format restatement within the broad skill's outcome."
- High H3: v1.1 unverified, raw outputs absent. Fix: rerun cases 01-04 GREEN plus RED, save to results/raw.
- Medium M1: gotcha-only subset. Fix: add "unique gotchas, evals, references" to the guard list.
- Medium M2: one-sided boundary. Fix: "a boundary stated by only one skill is current only if the other does not contradict it; count as needed if one-sided."
- Medium M3: chains of 4+. Fix: "A chain with no hub: NHR group, list pairs."
- Medium M4: description. Fix: start "Use when classifying duplicated or overlapping activation scope between Agent Skills (including a proposed new skill)"; delete "decide whether skills should merge" (replace "recommend merge or keep").
- Medium M5: eval contamination. Fix: add held-out cases using novel domains.
- Low L1: A-C pair. Fix: "A-C is reported as a sub-item and excluded from Pairs evaluated in explicit mode."
- Low L2: split Step 7 into cluster, hub, handoff bullets.
