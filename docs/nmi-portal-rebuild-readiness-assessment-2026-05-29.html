Section 1

Executive Decision Summary

Primary verdict
Refactor, not Rebuild.
2026-06-28 current-state refresh: The verdict remains unchanged, but the migration surface has grown. The app now uses React Router 7.18.0 and registers 41 paths, including six pattern/type approval routes. The current source has 31 top-level component families, 87 Storybook story files, 114 unit-test files, and 29 BDD feature files. Type-check, lint, 1,169 unit tests, and 218 Storybook interaction tests pass. The coverage command fails the configured 100% thresholds at 74.43% statements, 75.51% branches, 72.56% functions, and 74.92% lines, tracked as COVERAGE-GATE-001. The six Type Approval paths have isolated Storybook coverage but remain reviewed app-BDD exclusions, tracked as TYPE-APPROVAL-E2E-001.

The modernisation assessment HTML confirms "Refactor" at line 1411. The codebase has a sound layered SPA architecture, well-separated concerns, a working test stack, and no fundamental structural flaws that would necessitate a rebuild. Two conditions must be resolved before migration work can safely begin:

  1. The auth bypass mechanism was a critical security issue. REACT_APP_AUTH_BYPASS was a runtime-injectable env var with no NODE_ENV guard and hardcoded fallback mock credentials. Remediated 2026-05-29 — devAuth.ts deleted, all references removed from AuthenticatedElement.tsx, AccountProvider.tsx, env.ts, index.html, and webpack.config.js. Type-check passes clean post-change.
  2. PII was being logged to Azure App Insights. Full AccountDetails and AccountInfo objects (email, name, ABN, CRM GUID) were passed to telemetry in multiple route and utility components. Remediated 2026-05-29 — all 13 call sites scrubbed to pseudonymous projections ({ homeAccountId } / { crmQuoteRequestId }).

Challenge to rebuild assumptions

Nothing warrants a rebuild. The WizardForm engine is complex but has a defined contract. The Bootstrap/SCSS theme is a thick override layer but is self-contained. The auth layer is correctly architected.

Wizard/form architecture

Compound component: WizardForm > WizardStep > WizardRoutedStep (29 props). Each step is a Route in a nested Routes subtree. Step progression is linear and enforced by a render-time guard. Validation split: validateHard (submit) vs validateSoft (save-draft). 6 wizard flows.

Auth/session/API

MSAL v3 PKCE redirect flow. AccountProvider > AccountStateCtx + AccountDispatchCtx > hooks. AuthenticatedElement = PreConditions + MsalAuthenticationTemplate + ErrorBoundary. 11 NSwag-generated API client classes. acquireTokenSilent at 35+ call sites (no centralized interceptor).

Runtime config

env.ts reads 11 window.* globals (after auth bypass retirement). Startup guard console.errors (does not throw) for missing vars.

Styling

26 SCSS files: _variables.scss (NMI color tokens + Bootstrap 5 overrides), _bootstrap-import.scss (single @import shim), 22 component-level partials, media-print.scss, _replace-svgicons-csp.scss. Custom font: "Public Sans" (TTF only). NMI icon font: nmi-iconfonts.css (woff only, 55 icons).

Tests

The current unit suite passes 114 files / 1,169 tests. It covers auth, wizard behavior, generated-client boundaries, validation, storage, utilities, components, routes, configuration, route traceability, and Storybook drift. vitest.unit.config.ts enforces 100% thresholds over its declared handwritten runtime surface, but npm run test:unit:coverage currently fails at 74.43% statements, 75.51% branches, 72.56% functions, and 74.92% lines. The BDD source contains 29 feature files: 9 application features with 28 scenarios and 20 Storybook features with 129 scenarios.
