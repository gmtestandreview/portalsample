Use
[the file review rubric](../../skills/writing-skills/references/file-review-rubric.md).

failing file. The existing whole-skill audit rubric remains separate.

| ------------------------------------------ | -----: |
| P — Purpose and boundaries                 |     10 |
| K — Domain value/context cost              |     10 |

| A — Correctness and authority              |     15 |

Verified means inspected/executed; Supported means the source/contract supports
the claim; NHR means missing required outcome evidence. A faithful historical
failure or NHR record can be well authored. Unexecuted outcomes never become
PASS because of its score.

## Ten-stage assessment

| Stage               | Assessment and resulting action                                                                                                                                                                                 |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1. Boundary         | Retain Agent Skill lifecycle scope; exclude ordinary Markdown, generic linting and one-off project instructions. Sample direct, indirect, near-miss and ambiguous selection cases.                              |
| 2. Justification    | Reusable value is authority separation, evidence discipline, instruction-form choices, disclosure, and class-specific validation. Preserve specialized source material.                                         |
| 3. Classification   | Discipline entrypoint, supported by technique/reference/tool resources; classify files by actual consumer role.                                                                                                 |
| 4. RED              | Freeze package baseline; retain actual broken links/examples, gate ambiguities, malformed-input crashes, graph loss and independent regression failures. Do not invent weak baseline behavior.                  |
| 5. GREEN            | Add bounded contracts; fix evidenced defects at the owning layer; preserve public interfaces, intentional negative fixtures and unique knowledge.                                                               |
| 6. Disclosure       | Keep the entrypoint below its 200-body-line target; consolidate the index and route specialist methods, templates, tooling and history conditionally.                                                           |
| 7. Instruction form | Use output/field contracts for shape failures and observed predicates for conditional gates. Qualify empirical wording claims and prevent authority invention.                                                  |
| 8. Test             | Run real invalid/edge regressions, actual Graphviz and standalone SVG checks, filled templates, snippet parsing and fresh independent task applications. Distinguish selection, application and runtime events. |
| 9. Validate         | Check final frontmatter, package build/lock, source formatting, links, executable regressions and evidence freshness; retain unresolved runtime gates and legacy-tool conflict.                                 |
| 10. Auto-optimize   | Rescore each file after bounded fixes and independent review. New rubric/test resources are included. Stop at the achieved file threshold; do not manufacture client activation evidence.                       |

## Devil’s-advocate findings and repairs

- Copied web/MDX links, broken YAML/fences and incomplete templates could
  produce unusable artifacts. Repair paths, syntax, prerequisites and output
  contracts; instantiate both real templates with required NHR→hold outcomes.
- Provider/example guidance could be mistaken for universal specification or
  execution authority. Add provenance, client boundaries, host hierarchy and
  explicit non-execution limits.
- Selection proxies could be graded as runtime activation, and selection-only
  tests could demand task execution. Declare measurement targets, split their
  criteria and preserve the target in regression cases.
- Historical deployment decisions could be mistaken for current readiness.
  Preserve original results with scope/hash/provenance limitations and explicit
  fresh-campaign requirements.
- Malformed optional YAML, forbidden Unicode and filesystem errors could crash
  or contaminate public outputs. Normalize owning-layer failures and exercise
  real CLI/API regression boundaries.
- Graph rendering could silently lose graphs/labels/images, overwrite
  collisions, ignore flags or write through linked outputs. Preserve graph
  semantics in composed SVGs, enforce bounded input/output contracts and report
  failures honestly.
