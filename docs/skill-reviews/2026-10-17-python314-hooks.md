# Python 3.14 hook and watcher migration

## Outcome and scope

Upgraded only the hook/watcher paths requested by the user, from baseline
`527b01c4`. Python 3.14.7 is already installed; no interpreter installation or
system PATH change was performed.

- The Python 3.14 launcher now selects an actual Python 3.14.x interpreter,
  checking versioned executables, Windows `py -3.14`, then generic commands.
  Each isolated version probe has a three-second timeout. Other Python minor
  versions are rejected.
- The pre-tool wrapper uses that selector while preserving `-I -S`, stdin and
  current exit contracts. A missing, malformed or throwing helper now produces
  constant error text and exit 2; a missing guard retains its existing warning
  and exit 0.
- `.claude/settings.json` routes PostToolUse and watcher startup through the
  versioned launcher. CLI arguments, stdin, stdout, stderr and child exit status
  pass through. Watcher startup remains in the background.
- `scripts/pre_tool_use.py`, `scripts/post_tool_use.py`, `scripts/watcher.py`,
  `scripts/process_utils.py`, `templates/watcher.py` and
  `.claude/hooks/secret-scanner.py` declare Python 3.14 shebangs. The guard uses
  a native type alias; PostToolUse uses native annotations. This follows the
  [Python 3.14 annotation guidance](https://docs.python.org/3.14/whatsnew/3.14.html#deferred-evaluation-of-annotations).
- `ruff.toml` sets Python 3.14 only for those six files and `tests/hooks/*.py`.
  The global Python 3.10 target and lint rule selection remain unchanged.
- `tests/hooks/test_python314.py` covers interpreter selection, version
  rejection, timeouts/errors, configuration registration, actual launcher
  forwarding and imports of all six scripts. Existing PostToolUse/wrapper
  fixtures were updated for the new launcher dependency; four additional tests
  cover helper initialization failures.

The standalone watcher template remains self-contained. Unrelated utility
scripts, skill edits, payload schemas, queue sequencing and audit schemas were
preserved. Existing watcher processes were not restarted.

## Compatibility and remaining evidence

AMBER: the Windows migration behavior, regression suite and CLI checks pass,
with no known material defect in the scoped changes. POSIX execution,
Pylance/SonarLint and activation in a fresh Claude Code session remain
unverified. Seventeen pre-existing broad lint findings remain outside this
runtime migration. The Sonar server rejected fresh analysis with HTTP 403.

The supported hook/watcher launcher runtime is now specifically Python 3.14.x. A
machine with only Python 3.13 or 3.15 will receive a clear missing-runtime
error; the security guard blocks rather than silently substituting another
version. Payload behavior is preserved for tested calls on 3.14. Native
annotation/type-alias representation changes are intentional; no repository
consumer requiring the previous introspection representation was identified.

For manual execution use `node scripts/python314.mjs scripts/post_tool_use.py`,
or invoke standalone scripts with `py -3.14` on Windows / `python3.14` on POSIX.
The next Claude Code session will use the updated registered commands; that
fresh-session activation has not been exercised here.
